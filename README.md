## Overview

**FinTrack** helps an individual record where their money goes and who owes whom, without an account, a server, or an internet connection. All data stays on the phone.

### Problems it aims to solve
- Spending is scattered across cash, UPI and bank accounts, with no single picture of it.
- Informal loans between friends and family ("I lent Rahul 5,000") are tracked in memory or chat history, and partial repayments get lost.
- Many finance apps require sign-up and cloud sync, which some people do not want for personal money data.

### Implemented features
- **Quick add**: one sheet to add or edit expenses, income, transfers and debts, with delete and undo. New accounts and categories can be created in place.
- **Activity**: searchable transaction list with type and period filters.
- **Dashboard**: current balance, income and expenses for the month, "saved this month", a 2x2 grid including amounts you owe and are owed, top category bars, and recent transactions.
- **Debts**: record money you lent or borrowed, record partial repayments, mark as settled (forgives the remainder) and reopen, with a progress bar and overdue highlighting.
- **Repayment reminders**: optional notification on the due date, 1 day before, or 3 days before, scheduled with WorkManager so it survives a reboot.
- **Reports**: Week / Month / Year view, six-month income vs expenses chart, category comparison against the previous period, and automatic insights such as "You spent 20% more on Food than last month."
- Light and dark theme following the system setting.

### Not yet built
Budgets and spending limits, goals, recurring entries, CSV/PDF export, backup and restore, biometric lock, custom date range in Reports.

## Getting Started

**Requirements:** Android Studio (current stable) with **Android SDK 34** installed (SDK Manager, SDK Platforms tab, "Android 14.0 (UpsideDownCake)"), and an internet connection for the first Gradle sync.

1. Clone the repository:
   ```bash
   git clone https://github.com/<your-username>/FinTrack-AI-Assisted-Android.git
   ```
2. In Android Studio choose **File > Open** and select the project folder (the one containing `settings.gradle.kts`). Trust the project and wait for Gradle sync to finish.
3. Run the unit tests: right-click `app/src/test/java/com/fintrack/app/domain` and choose **Run Tests**.
4. Connect a phone with USB debugging enabled (or start an emulator), pick it in the device dropdown, and press **Run**. On Android 13+ allow notifications when asked, otherwise reminders stay silent.

Instrumented repository tests (`app/src/androidTest`) need a device or emulator: `./gradlew connectedAndroidTest`.

> A debug build is recommended. The release build type has code shrinking enabled and has not been tested.

## Architecture

```
app/src/main/java/com/fintrack/app/
├── domain/      Pure Kotlin, no Android imports: money, models, validation, FinanceCalculator,
│                dashboard / activity / reports / reminder logic
├── data/        Room entities, DAOs, database, FinanceRepository
├── reminders/   WorkManager worker and notification code
└── ui/          Compose screens and ViewModels: dashboard, activity, debts, reports, quickadd, nav, theme
```

All balances and totals come from `FinanceCalculator`, so screens cannot disagree with each other.

### Money rules (enforced in code and tests)
- Money is a `Long` in paise, never floating point.
- Transaction types: `EXPENSE`, `INCOME`, `TRANSFER`, `DEBT_OUT`, `DEBT_IN`. Only `EXPENSE` and `INCOME` count toward income, expenses and savings. Transfers and debts move balances only.
- A debt is a person plus linked transactions (principal and repayments). Outstanding is always computed (principal minus repayments minus any written-off remainder), never stored, so it cannot drift.
- "Mark as settled" forgives the remaining amount (stored as `writtenOffMinor`). No money moves, so balances do not change. "Reopen" clears it.
- Repayments cannot exceed the outstanding amount; this is checked inside the same database transaction as the insert.
- Every save carries a unique `requestKey`; a double-tap or retry is ignored by a unique index.

## Known Limitations
- Data lives only on the device; `allowBackup` is off and there is no export yet, so uninstalling the app deletes it.
- A reminder can only be set when a debt is created, not edited afterwards. The app cannot confirm that a notification was actually delivered.
- The Dashboard's "this month" is fixed when it loads; leaving the app open across midnight at month end shows stale numbers until the next change.
- Some phones (Xiaomi, Oppo and similar) delay background work for battery saving, so reminders can arrive late.
- The Gradle wrapper is not committed in this repository; Android Studio supplies Gradle when you open the project.
